# Remaining P0 integration contracts

Root owns Prisma schema/migrations, server.ts, global Flutter router/providers/auth/Today/Profile, medication feature and shared transaction helper. Workers own only assigned paths; coordinate shared changes through artifacts/messages. Existing Activity documentation edits belong to current user workflow and must not be overwritten accidentally.

## Goals schema (root will install)

BehaviorGoal: id/userId UUID, title String, goalType String(manual_checkins,activity_minutes,record_meals,record_glucose,walking_sessions), targetValue Decimal(12,2), period String(daily,weekly), startDate Date, endDate nullable Date, status String(active,paused,completed,archived), version Int default1, createHash String, createdAt/updatedAt TIMESTAMPTZ. user FK, checkins relation, revisions relation. GoalCheckin: id/userId/goalId UUID, eventAt TIMESTAMPTZ, status String(completed,skipped,unknown), value Decimal(12,2) default1, notes nullable, version1/createHash/archiveAt/createdAt/updatedAt and revisions. Add goalId/checkinId to exclusive RecordRevision source constraint. Check-ins manual confirmations, no glucose achievement scoring.

Goals endpoints resource pattern /api/me/goals and /:id; POST/GET /:id/checkins; PATCH /:id/checkins/:checkinId with correction version/reason; GET /:id/revisions and checkin revisions as needed. Exports goalsRoutes and goalsService with daily(userId,date?) plus owned list/get/create/update/checkin methods. Progress has explicit start/end period/source/coverage, distinct recorded days where appropriate. Derived activity sources exclude archived/needs_review. Active/pause/resume/completed/archive versioned with reasons; checkin requires active goal/date. Date-based week follows saved locale/timezone. Stable create UUID/hash; no ID ownership from body. Root offers inTransaction(callback,options?) helper (AsyncLocalStorage-flattened nested transaction) at shared/database/transaction.ts; use it in place of prisma.$transaction for writes so sync receipt/domain writes commit atomically.

## Medication schema/exports

MedicationRegimen: id/userId, name, strength, dosageForm, dosingInstructions, instructionSource(self_reported,clinician_reported), startDate/endDate Date, status(active,paused,inactive), version/createHash, createdAt/updatedAt. MedicationSchedule: id/userId/regimenId, localTime HH:mm, timezone IANA, daysOfWeek Int[] ISO1–7, enabled, effectiveFrom Date, disabledAt TIMESTAMPTZ nullable, createdAt. MedicationIntake: id/userId/regimenId/scheduleId nullable, scheduledAt nullable, takenAt nullable, eventAt TIMESTAMPTZ, status(taken,skipped,unknown), nameSnapshot/strengthSnapshot/formSnapshot/instructionsSnapshot, notes nullable, version/createHash/archivedAt/createdAt/updatedAt. Unique(scheduleId,scheduledAt) for one confirmation per occurrence. Revisions via regimenId/intakeId exclusive source keys. Schedules are versioned by disabling old rows; history snapshots preserved. No missed/adherence inference for unconfirmed doses. medicationService.daily(userId,date?) returns scheduled occurrences + confirmed counts; medicationRoutes exported. Intake creation POST /api/me/medications/:id/intakes, patch correction /:id/intakes/:intakeId.

## Summary projections

Root adds DailySummary and WeeklySummary: id/userId, summaryDate Date or weekStart Date, computationVersion, computedAt, coverageStatus, freshnessStatus(CURRENT,STALE), analyticsState(NOT_AVAILABLE,COMPUTING,READY,INSUFFICIENT_DATA,STALE,ERROR), metrics Json, unique(userId,date/version key). Read-model worker uses these names and fields; can request amendments before migration. Source writes mark user's projections STALE transactionally; read recomputes current daily/weekly source data. Stored projections derived only. No causal/clinical/TIR metric. Root updates recordAudit invalidation hook for domain event names with prefixes meal/glucose/activity/medication/goal and consent/preferences changes. inTransaction helper shares outer sync transaction.

Read-model routes: /api/me/timeline extends existing meal/glucose/activity with medication intake and goal checkin; stable opaque occurrence/domain/id cursor, owner-scoped date/type filters, source links. /api/me/insights, /api/me/summaries/daily (keep existing Nutrition top-level compatibility), /api/me/summaries/weekly. Full Flutter screens independent providers; root adds Routes.log=/log and Routes.insights=/insights under HomeShell TODAY|LOG|INSIGHTS|PROFILE and routes for source detail. Workers deliver hooks to invalidate their providers after changes. Timeline typed events include domain and recordId plus parentId for nested intakes/checkins; use that for original domain detail routing. Future unsupported/contextual analytics remain clearly unavailable, no invented correlations.

## Offline/server sync wire contract

POST /api/me/sync/operations body {operations:[{operationId UUID,domain:meal|glucose|activity|medication_intake|goal_checkin,recordId UUID,operationType:create|update,expectedVersion?:number,payload:object,parentId?:UUID}]} capped50. Each operation validated/session/consent/owner scoped and atomically applies domain write + durable receipt keyed(userId,operationId). Different payload same operationId409; retry returns stored result. Response {items:[{operationId,status:SYNCED|CONFLICT|NEEDS_REVIEW|SYNC_FAILED,recordId,result?:domainRecord,error?:{code,message}}]}. Unauthenticated entire request401; client never rebinds previous account operations to current token. GET /api/me/sync/status returns owned operation receipt summaries, no public health data. Sync is transactional per operation, not entire batch.

Root adds SyncOperation userId/opId/hash/domain/recordId/operationType/result Json/completedAt and ownership uniqueness. Root routes domain methods through inTransaction so nested source transactions share outer receipt. Offline worker provides durable encrypted per-account store using existing flutter_secure_storage (or coordinates necessary dependency), queue states DRAFT/SAVED_LOCAL/SYNCING/SYNCED/SYNC_FAILED/CONFLICT/NEEDS_REVIEW, serialized mutations/restart recovery, stable operations/record IDs and explicit retry/review/discard resolution. Cache/list/detail overlays use account-keyed records, never global in-memory health. Logout locks/isolate prior-user encrypted cache; consent withdrawal prevents processing/sync and clears or hides data appropriately. Existing repositories/forms will be integrated by root with worker's hooks, not duplicate forms. On local save, return usable provisional record with source payload plus local timestamps/version/status; server confirmation refreshes cache and summaries. Offline summaries must be labeled stale/unavailable rather than CURRENT invented metrics.
